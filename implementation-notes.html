実装ノート — G2 Battery の rate/eta を companion Items に出せるようにする

最終更新: 2026-06-02 / status: 実装完了・実機未検証 / config version bump: なし
問題設計判断変更 フロー逸脱/範囲トレードオフ確認事項

問題

companion の Items の G2 group に rate(消耗レート ↓N%/h) と eta(残り時間) が出てこない。原因は二重ゲート:
  1. 素材メタ(GroupMeta.segments)は syncSourceWithStatus が live status から拾った時しか追加されない(add-only)。ensureBuiltin は静的 seed しない。
  2. Items 描画は meta.segments ∩ 現在の live status しか描かない(companion.ts の if (!seg) return '')。
rate/eta は getBatteryDrainRate() が非 null の時だけ emit され、これは「非充電で実際に バッテリーが 60 秒以上のスパンで 2 点以上減った観測」が必要。よって充電中・短時間テスト・ WebView 終了では meta にも入らず Items にも出ず、事前にトグル/配置/表示条件を設定できない。

設計判断 decided

GPT-5.5(Codex)レビューで合意した A 案 = 概念的には 「Capability(設定面が見せる固定能力)」と「Status snapshot(実データ)」の責務分離。
  • builtin g2 は code 所有の固定 capability なので、素材メタに {level, rate, eta} を静的 seed する。
  • Items(設定面)は meta を表示ソースにし、live 値が無くても行を描く(値は — プレースホルダ、トグル/並べ替え/配置/条件は操作可)。
  • glass(実描画)は現状維持: live status にある segment だけ描く。StatusDoc は実データのみを保つ。
却下案
案判定理由
B: localStatus が空 sentinel を常時 emit + glass 側 skip非推奨StatusDoc の意味が汚染され、条件評価/並べ替え/同期に漏れる
C: ドキュメント化のみ不十分設定不能は実害

意図的な範囲限定 deviation

ユーザー選択は「全 source 統一」。segment 単位の placeholder 化は共有描画パスなので全 source に一律適用される (server source も一度観測した segment が live 欠落しても Items に残る)。 一方 group 単位の存在ゲート(companion.ts visibleRefs() / groupRow の if (!g) return '')は変更していない。 group ごと live 非存在(offline server / 電池無し)の時はその group 自体を Items に出さない。 理由: offline/未接続 source の group を全部 dash で並べるとノイズが増えるため。 ユーザーの実機は電池ありで g2 group は live 存在するので、本件は segment 単位の修正で解決する。

トレードオフ tradeoff

  • placeholder の表示条件エディタは seg.percent 不在で threshold 候補を出さない(onChange のみ)。builtin で live 欠落するのは rate/eta のみ=元々 onChange 専用なので実害なし。level は電池ありなら常時 live。既存 threshold 条件は leafRow の allowThreshold = hasPct || leaf.kind==='threshold' で温存。
  • seed は CONFIG_VERSION を bump せず、ensureBuiltin(全 load 経路)で additive・idempotent に補充。既存 v4 config も次回 load で rate/eta が後方補充される。
