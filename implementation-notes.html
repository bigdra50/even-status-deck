概要

グラス (G2 576×288・全面 1 TextContainer・最大 10 行) のナビを 「自動生成デッキ (auto)」一本から、ユーザーが明示設計する 「意図的マルチページ (explicit デッキ)」へ一般化した。view.pages: GlassPage[] を additive 追加し、scroll でページ巡回する。pages 未設定の profile は従来どおり auto デッキ (summary + group detail) で完全後方互換。

アーキテクチャ

flowchart TD store[store status] --> build["buildRuntimePages(d, visible)"] cfg["activeView(config)"] --> build build -->|"pages あり"| custom["custom デッキ: pages を空ページ skip"] build -->|"pages なし"| auto["auto デッキ: autoSummary + 描画可能 group の autoDetail"] custom --> deck["RuntimePage[]"] auto --> deck deck --> render["renderDeckPage(pages, idx, d)"] render -->|"explicit かつ 複数"| ind["本文 9 行 + 最終行ドットバー"] render -->|"auto / 単一"| full["本文 10 行 (インジケータ無し)"] ind --> tc["単一 TextContainer content 差し替え (ちらつき無し)"] full --> tc

ナビ: scroll↓/↑ = 次/前ページ (wrap) ／ tap = 先頭 ／ double-tap = 終了。 coalesce は既存 refreshBusy/refreshPending 直列化を流用 (追加実装なし)。

設計判断 decided

グローバル glassLayout 参照を「対象ページの layout を引数で受ける」へリファクタ

renderKeys / layoutRowClusters / layoutLines が activeView().glassLayout をグローバル参照していた。ページごとに layout・customLabels が変わるため、customLabels / lay を引数化。 これによりページ A の customLabels がページ B に漏れない (unit で固定)。

companion は editingLayout() で「現在編集中ページ」を 1 点に集約

20 箇所超の activeView(config).glassLayout 参照を editingLayout() = activeView(config).pages?.[pageEditingIdx]?.layout に集約。auto デッキ (pages 未設定) は従来 UI、explicit デッキはページ tab + 選択ページ編集。

migration: backfillPages を全 glassLayout remap の「後」・pruneOrphans の「前」に配置

各 migrate 関数で glassLayout を remap するヘルパ群 (location merge / clock 統合 / mac→system) の後に backfillPages を 1 回走らせ、remap 済みの値を pages[0] へ投影する。pages[0].layout は cloneGlassLayout による deep clone で glassLayout と参照を切る (editor が両方を書き換える二重真実を防ぐ)。glassLayout は読込互換で残す (spec §8)。CONFIG_VERSION 4 → 5。

id remap / clock 統合を全 profile + pages へ拡張 (codex レビューで発見)

reKeySource / mergeSourceViewInto は接続テスト (runtime) で走るため、 pages の segKey も remap しないと merge / id 安定化で配置が壊れる (e2e source-stability が捕捉)。consolidateClock は active profile のみ remap していたため非 active profile の pages に旧 time/date が残る問題を、全 profile 対象に修正。backfill 前のヘルパは壊れた pages (layout=null) に触れるため null ガードを追加。

逸脱 deviation

ページインジケータ: auto デッキは非表示・explicit デッキのみ表示 (spec §6「一律」から逸脱)

spec §6 は「auto / explicit 一律でドットバー表示」と確定していたが、auto デッキでも group が 1 つあれば summary + detail で 2 枚以上になり、既存 summary が黙って 10 → 9 行に減る回帰が出る。codex (gpt5.5) と議論し、 「既存 auto profile の表示互換を守る方が、auto のページ位置喪失より重要」と一致。 explicit デッキ (新機能) のみ 9 行 + ドット、auto と単一ページは 10 行フル。 ユーザー承認済み。将来 view.indicator: auto|hidden|dots の opt-in で一律化を選べる余地を残す。

トレードオフ tradeoff

explicit デッキ・複数ページ時、10 行目の chip はインジケータに隠れる

インジケータ表示時は本文予算 9 行。ユーザーが 10 行目に置いた chip は出ない。 companion の編集画面に注意文 (「row 10 is hidden behind the page dots」) を表示して緩和。

pages 化で companion を pages 主体に寄せ、glassLayout は legacy 読込専用に

backfill 後は resolvePages 経由で render は pages を見る。glassLayout は当面残すが書き込みは pages へ。次バージョンで削除可否を判断 (spec §8)。

未解決・後追い open question

項目現状方針
tombstone (削除→同 machine 再追加) の pages 配置復元 pages 非対応 (glassLayout のみ復元) 削除→再追加で pages 配置は失われる。構造変更が大きくレアなので後追い。
「10 行目だけに chip があるページ」の空ページ判定 MAX_ROWS で live 判定 (複数デッキでは本文 9 行) 複数時に本文空 + ドットのみになりうる。companion 警告で緩和。閾値変更は単一ページ副作用ありで保留。
auto デッキのインジケータ opt-in 非表示固定 view.indicator 設定で将来選択可能に。
ドット ●/○ の実機描画 シミュレータ確認・実機未確認 tofu なら indicatorLine を i/N / =/- へ。>8 ページは既に i/N fallback。
