概要

segment の visibility 条件成立時に、inline 常時表示の代わりに実装済み overlay UI (toast / banner / notification / dialog) のいずれかを選んで提示できるようにした。 提示先は Persistent(既定=現状 inline) を含む単一選択。基盤(overlay 描画)は既存を再利用し、 新規は「条件 → いつ撃つか」の trigger 層。

正しさの要点 decided

  • tri-state 発火: inline は fail-open(na→出す) だが、通知は known-false→known-true のみ。na(位置不明/percent 欠落)では撃たない。
  • runtime instance 分離: main.ts が実機で companion と glass を両 mount → singleton 共有だと preview が edge を消費。glass/preview で分離。
  • seed vs observe: init/config 変更は seed(発火させない=起動ストーム/編集中誤発火を防ぐ)。発火は store 更新のみ。banner は level なので seed でも表示。
  • unknown 温存: offline で source が statuses から消える→key 欠落→unknown。edgeState を温存し再接続で誤再発火しない。banner は一旦 clear し再接続 known-true で再表示。
  • cooldown: per-key 30s。onChange leaf + display は構造上「変化ごと」なので必須。fires-per-observe と toast queue を上限化。
  • 不変条件: 発火は computeVisible の外 (glass shell)。companion preview は別 instance で発火しない。
  • overlay.key() を content-hash 化: 旧実装は文字数比較で、同長別内容の banner/toast 値更新が再描画されなかった (codex 指摘) のを修正。

v1 範囲外 (additive に拡張可) deferred

  • per-condition duration / dialog の action 束縛 (preset 切替等)。dialog は ack-only。
  • enqueue TTL・同一 key coalesce は cooldown(30s)+queue 上限で実用上カバー。必要なら追加。
  • condition banner と server 由来 banner は 1 スロット共有。条件 banner が占有中は毎 observe で再 set されるため server banner より優先される (none のときは server を温存)。
  • reload 跨ぎの edge 取りこぼしは許容 (seed-only)。
  • strict arm: 起動/接続直後に既に条件が true でも発火しない (一度 false を観測してから true で発火)。 cold-start storm を避けるための意図的トレードオフ (codex の seed-only 設計)。レビュー指摘 C1 を storm 回避優先で strict 維持。 「既に true なら起動時に一度出す」が必要なら warmup 追跡を足す additive 拡張で対応可。
