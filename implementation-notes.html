背景

従来の表示条件 (SegMeta.visibility) は leaf が常に self (その segment 自身) を評価対象にしていた。 threshold は self の percent、onChange は self の value 変化。 「同一 group の別 segment B がある条件を満たしたら A を表示する」という相互参照が表現できなかった。 例: G2 group で battery level ≤ 20% のときだけ eta を表示。

設計判断 decided

ユーザー承認: peer テストを 3 種すべて実装 (しきい値 / 存在 / 変化)。スコープは同一 group 内。 モデルは P 案 + present 新 kind (codex GPT-5.5 が支持):
  • threshold / onChange に optional seg?: string を足す。省略=self (後方互換・移行不要)、指定=同 group の兄弟 segment。
  • 存在判定は self では自明なので peer 専用の新 kind { kind:'present'; seg; absent? } を足す。
  • targetRef オブジェクト化等の汎用化は今回過剰として却下 (YAGNI)。

モデル decided

type VisibilityLeaf =
  | { kind:'threshold'; op:'lte'|'gte'; value:number; seg?:string }  // seg省略=self / 指定=兄弟のpercent
  | { kind:'onChange';  holdMs:number;               seg?:string }  // seg省略=self / 指定=兄弟のvalue変化
  | { kind:'inPlace';   placeId:string; outside?:boolean }
  | { kind:'present';   seg:string; absent?:boolean }               // 兄弟が値を持つか(absent=空か)
循環参照は起きない。条件は live status の値だけを見て相手の可視“結果”を見ない。 B が profile 上 hidden でも B の live 値で A を制御できる (むしろ望ましい挙動)。

評価意味論 (tri-state) decided

leaf対象不在時備考
threshold (self)self.percent—self は必ず存在。percent 欠落='na' (従来どおり)
threshold (peer)兄弟.percentfalsepeer 不在を 'na' にすると単独条件で fail-open 常時表示になり矛盾。peer あり percent 欠落は 'na'
onChange (self/peer)対象.valuefalse不在=変化観測不能。状態キーに対象 id を含め切替直後の誤発火を防ぐ
present兄弟.valuefalse常に bool (不在検出が目的)。value.trim()!=='' を has とし absent で反転
onChange の状態キー: ${segKey}#${i}:${leaf.seg ?? self.id}。host 基準に対象 id を付与し、 self→B / B→C と対象を切替えた直後に前の対象の prevValue と比較される誤発火を防ぐ。

codex (GPT-5.5) レビュー反映 tradeoff

  • High: threshold peer 不在を 'na' でなく false に (fail-open 矛盾の回避)。採用。
  • Medium: onChange 状態キーに対象 id を含める。採用。
  • Medium: threshold 可否を self でなく group の percent で判定、保存済み対象は live 消失でも select に残す。採用。
  • self 選択時は delete leaf.seg で省略形へ戻し config churn を回避。採用。
